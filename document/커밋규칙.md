# 🧾 커밋 규칙 (Commit Convention)

> 커밋 메시지는 **한눈에 변경 의도를 파악할 수 있도록** 명확하게 작성한다.  
> 도구로 강제하지 않으며, 아래 규칙은 **권장 가이드라인**으로 적용한다.

---

## 🎯 1️⃣ 기본 원칙

- **한 커밋 = 하나의 의미 있는 변경**
- 커밋 메시지만 보고 **무엇을, 왜 수정했는지 이해 가능해야 함**
- 사소한 수정(오타, 공백 등)은 기능 커밋과 분리하여 관리
- 영어 또는 한글 사용 가능 (되도록 일관된 언어 유지)

---

## 🧩 2️⃣ 커밋 메시지 구조

```
<type>(<scope>): <subject>

<body>
```

- `type`: 변경의 유형  
- `scope`: 변경된 영역 (선택사항)  
- `subject`: 한 줄 요약 (마침표 `.` 없이 간결히 작성)  
- `body`: 상세 내용 또는 변경 이유 (선택)

---

## 🏷️ 3️⃣ Type 종류

| 타입 | 설명 | 예시 |
|------|------|------|
| **feat** | 새로운 기능 추가 | `feat(order): 주문 생성 기능 추가` |
| **fix** | 버그 수정 | `fix(auth): 로그인 토큰 만료 오류 수정` |
| **refactor** | 코드 리팩토링 (기능 변경 없음) | `refactor(product): 가격 계산 로직 분리` |
| **style** | 코드 스타일, 포맷 변경 | `style: 불필요한 공백 제거 및 포맷팅` |
| **docs** | 문서 수정 | `docs: README 실행 방법 추가` |
| **test** | 테스트 코드 추가/수정 | `test: OrderService 단위 테스트 추가` |
| **chore** | 빌드/설정/배포 등 관리 작업 | `chore: Dockerfile base image 변경` |
| **perf** | 성능 개선 | `perf(redis): 캐시 조회 속도 개선` |

---

## 🧭 4️⃣ Scope 예시

> scope는 선택적으로 사용하며, 변경된 주요 영역이나 모듈을 나타냄

| 예시 | 설명 |
|------|------|
| **backend** | Spring Boot 관련 백엔드 코드 |
| **frontend** | Vue, UI 관련 코드 |
| **api** | REST API, DTO 등 |
| **db** | 쿼리, 테이블, 마이그레이션 |
| **infra** | 배포, 서버 설정, Jenkins, Docker |
| **design** | UI/UX, Figma 등 |

---

## ✍️ 5️⃣ Subject 작성 규칙

- 간결하고 **명령형**으로 작성  
  - ✅ `add`, `change`, `remove`, `fix` 등 동사 형태 권장  
  - ❌ `added`, `changed`, `fixed`
- 50자 이내로 간단하게 요약  
- 마지막에 마침표(`.`) 붙이지 않음  
- 예시:
  ```
  feat(product): 상품 등록 시 유효성 검증 추가
  fix(order): 주문 상태 업데이트 오류 수정
  ```

---

## 💬 6️⃣ Body 작성 가이드 (선택)

- 변경 이유나 주요 수정 내용을 서술
- 한 줄 요약으로 부족할 때 사용
- 예시:
  ```
  feat(order): 주문 생성 기능 추가

  - 결제 완료 시 상태를 PAID로 변경
  - 주문 생성 시 재고 검증 추가
  - OrderService 및 OrderRepository 추가
  ```

---

## 🧠 7️⃣ 기타 권장사항

- 여러 파일 수정 시, **기능 단위로 나누어 커밋**
- 오탈자, 포맷 수정 등은 `style:` 또는 `chore:` 로 구분
- 커밋 메시지 언어는 프로젝트 내에서 **일관되게 유지**
- 필요 시 이슈 번호나 참고 링크를 Footer에 추가  
  예: `Closes #23`, `Refs #42`

---

## 🪄 8️⃣ 커밋 예시 모음

```
feat(auth): JWT 토큰 발급 로직 추가
fix(order): 재고 부족 시 예외 처리 추가
refactor(balance): BalanceService 로직 분리
style: 코드 포맷 통일
docs: CONTRIBUTING.md 추가
test: ProductService 단위 테스트 추가
chore: npm 패키지 업데이트
perf(redis): 캐시 조회 속도 개선
```
